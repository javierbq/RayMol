# Morph Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn any multi-state object into a smooth, looping `<source>_morph` object from the Object panel and the Movie tab, computed off the main thread with progress and cancel, without touching the source.

**Architecture:** A Python job layer (`morph_jobs.py`) wraps the existing POC engine (`morphing.py`): it snapshots coordinates on the main thread, computes legs on a worker thread that never touches `cmd`, and lands frames through a budgeted `pump()` driven by the existing 500 ms Object-panel poll. The app learns about morphs the way it learns about predictions: a `morph_jobs` map in the OBJPANEL payload feeds the ProgressTray, and a `morph` map tells the panel which objects are morphs. Swift adds one settings model, one sheet, a capsule on the State row, and a toggle in the Play-models sheet; the timeline needs no new clip kind.

**Tech Stack:** Python 3.13 (embedded; pure lists, no numpy), PyMOL `cmd` API, SwiftUI (macOS + iOS), XCTest, `testing.PyMOLTestCase`.

**Spec:** `docs/superpowers/specs/2026-10-21-morph-design.md`

## Global Constraints

- Branch `worktree-morph-poc` (worktree `.claude/worktrees/morph-poc`); never commit to `master`; open a PR into `master` at the end.
- The embedded core is main-thread only: worker threads may compute and print, never call `cmd` (spec §4).
- Python read of coordinates uses `iterate_state` (lists); `cmd.get_coords`/`get_coordset` return `None` in the shipped app (spec §4).
- Output object name `<source>_morph` (legalised with `cmd.get_legal_name`); `_morph2`, `_morph3`… only when the name is taken by a non-morph (spec §5.1).
- Only `alt ''+A` atoms are carried; discrete sources and per-state atom-count mismatches are refused with `morph: models have different atoms; morph needs the same atoms in every model` (spec §5.2, §5.9).
- Key frames at `1 + k·frames_per_model` are bit-exact copies of models and are never sculpted; `loop=1` → N legs, `loop=0` → N−1 legs; state count `= legs × frames_per_model` (spec §5.2).
- Defaults: frames per model 15, loop on, method `rigimol`, clean-up 3, rate `linear`; Movie-tab toggle off (spec §5.3, §5.7).
- Memory thresholds: warn above 200 MB macOS / 100 MB iOS, refuse above 1 GB / 400 MB with `Reduce frames per model or morph fewer models` (spec §5.6).
- Movie fps (`movie_fps`, default 30, mirrored as `engine.playback.movieFPS`) is the canonical fps for the summary and auto-play; the morph's per-object fps is set to it (spec §5.3).
- Surface and mesh reps are cleared on the morph; look copy transfers only explicit object-level settings (`cmd.get_object_settings`) and never `state`/`all_states` (spec §5.5).
- Full-range Movie clips send `last = 0`; `StatesSpec.morphStride` remaps model indices at rebuild (spec §5.7).
- Every new `PanelPayload` field is `Optional` (spec §4).
- Python snippets sent from Swift import what they use and escape arguments with `InferenceJob.pythonLiteral`; object names must pass `isLegalObjectName` (spec §4).
- New Python test files must be added to `.github/workflows/raymol-embedded-tests.yml` or they never run.

## Review Focus

1. **Morph pressed twice while the first job is still running** — the second press must be refused with `morph: <name> is already being built`, not start a second job over the same object (Task 3 test `testStartTwiceIsRefused`).
2. **Source deleted while its morph computes** — `pump()` must not raise, must mark the job `error` with `morph: source <name> was deleted`, and must delete the partial morph (Task 5 test `testSourceDeletedMidJob`).
3. **Residue numbering with insertion codes or negative numbers** — segmentation must walk residues in `(resv, resi)` order, not string order, or hinges land on the wrong residues (Task 1 test `testInsertionCodesOrder`).
4. **Movie fps of 0 or a two-model source** — `naturalSeconds` and `absoluteRange` must not divide by zero or produce an empty range (Task 6 tests `testNaturalSecondsGuardsZeroFPS`, `testAbsoluteRangeTwoModels`).
5. **Morph created while the timeline is open** — the row is selected but playback must not start, because inspection playback is disabled while authoring (Task 7 test `testCompletionPlanRespectsTimelineMode`).

- Produces:
  - `class MorphJob` with attributes `name, source, spec (dict), fingerprint, legs, frames_per_model, done_legs, landed_legs, state ('queued'|'running'|'done'|'error'|'cancelled'), error (str|None), started (monotonic)`, methods `step() -> bool` (computes the next leg into an internal queue; False when none remain), `cancel()`.
  - `start_job(source, name=None, frames_per_model=15, loop=1, method='rigimol', refinement=3, rate='linear', copy_look=1, _self=cmd) -> MorphJob` (validates, creates the object with state 1, copies look, registers in `_JOBS`; raises `morph: <name> is already being built` when a job for that name is not terminal; refuses on `morph_estimate(...)['refuse']`).
  - `pump(budget_ms=100, _self=cmd) -> None` (lands queued legs, sculpts landed intermediates via `morphing.sculpt_states`-style per-state calls, writes titles, finishes jobs; stops when the budget is spent; never raises).
  - `morph_object(source, name=None, frames_per_model=15, loop=1, method='rigimol', refinement=3, rate='linear', copy_look=1, async_=1, reuse=0, quiet=1, _self=cmd) -> str`; with `async_=0`: `while job.step(): pump(budget_ms=10**9)` then one final `pump`. With `reuse=1`: when a `done` job exists for the target name whose spec equals the requested spec and whose fingerprint equals `fingerprint(source)` now, return the name without rebuilding (spec §5.7).
  - `morph_cancel(name, quiet=1, _self=cmd)`; `morph_spec(name) -> dict|None` (`{'spec', 'fingerprint', 'state', 'started'}` for every job this session, terminal included); `pending_objects() -> {name: [name]}` (non-terminal jobs); `recent_objects() -> [name]` (retained `error`/`cancelled` records until dismissed); `pending_info(name) -> dict|None` with exactly the keys `designing.pending_info` publishes: `state, phase, fraction, moving, models_done, models_total, elapsed, error, detail, bundle, step, total_steps, remaining, batch, batch_index, batch_total, run_remaining` (`models_done=landed_legs`, `models_total=legs`, `fraction=landed_legs/legs`, `phase='computing'|'landing'|'done'`, `detail='leg k of N · P%'`); `morph_dismiss(name, quiet=1, _self=cmd)` drops a retained record; `morph_sources() -> {morph_name: {'source': str, 'spec': spec_dict}}` for completed morphs that still exist.
  - On completion: hide the source (`disable`), verify state count and last-frame round trip, record `done`, remove from pending (a successful job leaves no tray record).
  - On error/cancel: delete the partial object, re-enable the source, retain the record.
