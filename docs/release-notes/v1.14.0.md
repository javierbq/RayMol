## RayMol 1.14.0

A feature release built around **morphing**: an NMR ensemble, trajectory snapshots or a set of predicted models now glides from one model to the next instead of flipping, in the viewport, in Timeline movies and in exported videos. Plus Timeline movies that are saved with your session, labels at the right size on Retina displays, tables in Notes, a side panel that copes with narrow windows, and more for AI clients that drive RayMol.

### Morphing

- **Turn a multi-state object into a smooth morph.** Expand the object in the **Objects** tab and select **Morph…** on the line under its State slider. RayMol computes the frames between consecutive models (15 per model by default) and stores them as a new object, `<name>_morph`, next to the original. A 20-model ensemble becomes a 300-frame morph, a 10-second loop at 30 fps. The original keeps its models and is only hidden once the morph is complete.
- **The models themselves are untouched.** Every original model is a key frame, copied exactly; only the frames in between are computed. With **Loop back to model 1** on, the last model morphs back into the first, so playback loops.
- **Rigid segments or Linear.** The default method splits each chain into rigid segments at the hinges where two models differ and moves each along a screw path, so parts that rotate keep their shape. **Linear** moves every atom in a straight line: faster, but rotating parts can distort. A clean-up pass (0–10 cycles) then relaxes the in-between frames with the backbone held fixed.
- **Builds in the background.** Keep rotating and restyling while it builds. A card in the progress tray shows the leg and percentage, with **Cancel**. The Morph sheet shows the frame count, length, memory and build time before you start, warns when a morph is large, and refuses one that would not fit in memory.
- **Rebuild or delete.** **Morph…** on the morph's own row reopens the sheet with the settings that built it; rebuilding keeps the name, so movie clips and scenes that use it keep working. **Delete morph** brings the original back.
- **Smooth transitions in a movie.** In the **Movie** tab, a **Play models** clip has a **Smooth transitions (morph)** toggle: **Add** builds the morph and appends a clip that plays it. Start and End still count models, so a Start 3, End 8 clip stops exactly on model 8, and Sweep, Loop and Lockstep all work. Exported videos play the morph frame by frame.
- **Playing a long morph keeps memory in check.** RayMol used to keep the drawn geometry of every frame it had shown, so memory grew as a morph or trajectory played. It now keeps what is on screen plus a bounded amount for frames that are not (1 GB by default on the Mac), and rebuilds an older frame when it is shown again. `set metal_gpu_cache_mb, 2048` raises the amount; a negative value removes the limit.
- **Or type it.** `morph_object 2kpo` does what the sheet does (`frames_per_model=`, `loop=`, `method=linear`, `refinement=`, `rate=`); add `async_=0` in scripts to wait for it. `morph_cancel` and `morph_dismiss` stop a build and clear its card.
- **Morph between two structures.** PyMOL's `morph` command works in RayMol: `morph mout, 1akeA, 4akeA` interpolates between two aligned objects, such as the closed and open forms of an enzyme.

A morph does not carry surfaces or meshes (one would be built per frame), and the models must all hold the same atoms. See the [Morphing guide](https://javierbq.github.io/RayMol/guides/morph/) for every setting, the memory limits and what a morph does not carry over.

### Movies

- **Timeline movies are saved in sessions.** A `.pse` now keeps the Timeline lane (camera keyframes, scene markers, Play-models clips, their durations and easing) along with the movie, so reopening the session brings the lane back ready to edit. Sessions saved by earlier versions open with an empty lane and their movie as it was.
- **Models hold still outside their Play-models clips.** With Sweep or Loop, an ensemble stays on its clip's first model before the clip and on the model it ended on after it, instead of drifting through a Roll or a scene transition placed around it.
- **Fixed: the Timeline lane sat too high and its scroll bar overlapped the Scenes strip** when macOS shows scroll bars all the time.

### Viewport and windows

- **Fixed: labels were drawn at half size on Retina displays.** A 14-point label is now 14 points, as in PyMOL. Label connectors and selection dots scale with it, and so do labels in exported images.
- **The side panel copes with narrow windows.** Below about 760 points wide the side panel hides by itself and comes back when you widen the window; opening it while the window is narrow (the tongue, or **View ▸ Show Side Panel**, ⌘3) shows it over the whole window. It is no longer squeezed below the width of its tabs.
- **The Mouse panel follows your theme.** Its controls and icons use the theme's accent colour instead of mixing it with the system accent.

### Notes

- **Tables in Notes.** Markdown pipe tables render as tables in the Notes preview, with column alignment, and export as real tables to HTML and PDF.

### AI clients (MCP)

- **AI clients know what RayMol can do.** The built-in MCP server now tells a client that RayMol is not stock PyMOL and gives it tools for studio lights, haze and dust, materials, render effects, image and movie export, on-device structure prediction and RayMol's own command help, so an assistant uses RayMol's renderer instead of falling back on `ray` and `png`. Morphs are reported too, so an assistant can start one and wait for it.
- **The "Claude is controlling RayMol" banner floats over the viewport.** It no longer pushes the whole window down and back each time a client sends a command.

### Other fixes

- **Fixed: a crash when a scene was deleted or replaced** while its thumbnail was still waiting to be drawn, and a queued thumbnail landing in the wrong scene.
- **Fixed: a `png` or `draw` issued from a script could be dropped, or crash,** when it queued more work while the queue was being processed.
- **Fixed: Design mode's saved look could be overwritten** by a second RayMol running at the same time.

Built on the open-source PyMOL engine. Updates install automatically via the in-app updater (**Check for Updates…** in the app menu).
